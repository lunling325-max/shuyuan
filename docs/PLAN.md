## 1. 一句话定位

> 不是又一个文献 Chatbot，而是**每句话都能点回原文精确位置的版本感知科研 Agent**。

卖点不是"答得好"，是**答不了的会当场被拦下**：每条结论都要逐字回溯到原文的
页码与坐标框，核对不上就不展示，并说明拦在哪一步。

## 2. 实际技术栈

单进程、单命令启动，运行时依赖一共 8 个（`apps/api/pyproject.toml`）。

| 层 | 用了什么 | 关键理由 |
|---|---|---|
| 前端 | 单文件 `apps/web/index.html`（4100+ 行，无构建步骤） | 评测机器上不用装 Node；`uv sync` 之后只有一个进程 |
| 解析 | PyMuPDF 1.28 + RapidOCR（PP-OCRv4 的 ONNX 版） | 表格网格、词级坐标、扫描件识别都在同一套依赖里 |
| 检索 | 自研 BM25 + 单复数归并 + RRF 融合；可选 BGE-small 的 ONNX 通道 | 12 篇文献的规模下，向量库的增益低于"多一个服务就多一个起不来的可能" |
| 生成 | DeepSeek（HTTP），不可用时整条链路降级而不是报错 | 断网/欠费时演示不能白屏 |
| Agent | 自研 planner：两阶段规划 + 动态重规划 + 10 个工具 + 参数校验 | 一轮运行上限 9 步，状态机换不来什么，却要绑定框架的 schema |
| 图论 | 手写 PageRank 与力导向布局（`app/citegraph.py`） | 算法本身二十行，不引 networkx |
| 存储 | 每篇一个 JSON sidecar + 磁盘缓存（OCR / 图表） | 单机单用户，数据量小；代价见 §4 |

## 3. 原计划里被砍掉的东西，以及砍的理由

| 原计划 | 换成 | 理由（可核对） |
|---|---|---|
| Next.js 14 + TS + Tailwind + shadcn | 单文件 HTML/CSS/JS | 没有构建步骤就没有"npm 装不上"这一类故障；评委 clone 下来只需要 uv |
| LangGraph 编排 | 自研 planner（`app/agent/planner.py`） | 单进程、单用户、9 步上限；工具注册表 + Pydantic 校验已经覆盖"模型给的名字和参数都不可信"这件事 |
| Qdrant + BGE-M3 + bge-reranker | BM25 + RRF + 可选 BGE-small ONNX | 实测密集通道在"中文问英文库"上要配检索词扩展才有效（E-004）；先证明词法够用，再谈向量 |
| PostgreSQL | JSON sidecar | 没有并发写、没有跨表查询；换来的是"删一篇文献要同时删内存、sidecar、落盘副本"这类一致性坑（E-017 真翻过车） |
| PaddleOCR | RapidOCR | 同是 PP-OCRv4 的中英模型，纯 wheel 随 `uv sync` 装好；Tesseract 要另装可执行文件与语言包，装不上这条用例就是 0 分（E-018） |
| PDF.js 阅读器 | 按块渲染正文 + `#page=N` 跳浏览器内置查看器 | 阅读器要的不是另一份 PDF 渲染，而是"这一句在第几页、哪个坐标框" |
| Matplotlib 出图 | 手写 SVG（`app/analysis/chart.py`） | 零依赖、能导出源码、图注里的数字可以逐个核验（编造的替换成 `[未核实]`） |

## 4. 范围：深度优先，但深度花在哪

原计划把六个模块平铺。实际做下来，时间几乎全花在**能被验证**的地方：

| 模块 | 做了什么 | 验证方式 |
|---|---|---|
| 解析与去重 | 结构感知切块、版本谱系、扫描件 OCR | 扫描件与原矢量版的章节树/参考文献逐条比对（23/3/20 条，36 条） |
| 抗幻觉 RAG | 三级匹配校验、坐标回填、`mode=retrieve` 兜底 | 每条结论给出 supported/weak/unsupported 与原因 |
| 引用图谱 | arXiv 号优先、标题次之的引用识别 + PageRank | 真引用标题 Jaccard 1.00，最像的假引用 0.50，阈值因此定 0.70 |
| 多模态 | OCR + 表格行×列还原 + 插图缩略图 | 表格：Transformer 的 Table 2 还原出 11 行、GPT-3 的 Table 2.1 还原出 9 行（E-019） |
| 联动阅读 | 中英逐段对照、引用双向跳转 | 段数对不上就整段降级，不硬凑 |
| 写作与可视化 | CSV → SVG 图 + 数字核验过的图注 | 图注里的每个数字都要能在数据里找到 |

## 5. 风险登记：哪些真发生了

| 风险 | 实际发生了什么 | 现在怎么兜 |
|---|---|---|
| 541 页的书塞爆上下文 | 没发生 —— 切块后逐块检索，解析走线程池 | `/api/health` 在大书解析期间照常响应（E-017） |
| OCR 慢到卡死请求 | 真发生了：6~9 秒/页 | 结果落盘 + 懒解析，同一份 PDF 只算一次 |
| 演示时大模型断供 | 真发生了：重启服务撞上 arXiv 限流，推荐页整页空白 | 依赖模型的接口返回 200 + `degraded`，检索与溯源照常可用 |
| 竞品功能更多 | 不追了 | 每加一个功能都要能说清"它在哪条主线上"；说不清的就不加 |
